# WotR Trash Loot Reference

## What "trash" means
1. **Random trash pools**: `TrashLootSettings` blueprints. `Types` = items per `TrashLootType` category, `Table` = category weights per `LootSetting`, `SuperTrashLoot` = junk pool per `LootSetting` (1–3 items + 1–20 gold).
   - `Root/TrashLootSettings.jbp` (`b2554a2be56f1c6478c14a442b0f64f3`): main pools. Placed `LootType.Trash` chests were filled from these ahead of time and stored in the blueprint.
   - `Root/TrashLootSettings_DLC3.jbp` (`77fe4de4c707e51439971ee480e94efc`): DLC3.
   - `World/Areas/Random_Encounters/RE_TrashLootSettings.jbp` (`daf5872cc909705428f4a092d05351d1`): random encounter chests (`CombatRandomEncountersGenerator.GenerateChests`) and `ContextActionAddRandomTrashItem`.
2. **Per-item tags**: `BlueprintItem.m_TrashLootTypes`. In code, the tag only stops `Equipment`-tagged items from stacking in `TrashLootSettings.RandomizeLoot`.
3. **Vendor cleanup**: `VendorLogic.IsTrashItem(ItemEntity)` is a code rule, not a list. An item is not trash if it is notable, a key, has enchantments/`AddFactToEquipmentWielder` (for one specific `ItemsFilter.ItemType`, value 11), or is equipment granting an ability.

## Roll logic (`TrashLootSettings.RandomizeLoot`)
- Budget = `CRToCost[cr]`; slots = `1 + cr/5 (+1 if cr%5 != 0)`.
- Each slot: weighted category from `Table`, then a random item from `Types[category]` with cost ≤ remaining budget (5 tries).
- Extra copies roll against `ChanceToIncreaseItemsCount`; leftover budget is paid out as gold (`SystemMechanics.GoldCoin`).

## Modding note
Editing the `Types` lists (e.g. `BlueprintsCache.Init` postfix) changes random encounter chests and trash-item actions. It does not change placed main-game chests, because their contents are already stored in the blueprint.
